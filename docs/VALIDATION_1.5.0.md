# 1.5.0 发布检查

日期：2026-11-06。MuMuPlayer 国际版 5.30.2.3616 / Android 12（SDK 32），MAA 6.21.4。仅记录本轮实际完成的项目。

| 项目 | 结果 |
| --- | --- |
| 旧版内核适配 | 确认缺少 `xt_owner`，采用 socket UID 的 eBPF 选择器；IPv4、IPv6 规则均写入后核对 |
| 作用范围 | 桌面 UID 的已知推广 HTTP 请求被拒，普通 shell UID 对相同地址可收到正常响应；测试 App 的普通 HTTPS 请求成功 |
| 商店差异 | 处理无商店的初始状态、后续安装商店的状态，以及旧商店仅声明两个已知追踪组件的情况；保留安装服务 |
| 原桌面 | 保留 MuMu HOME，不安装替代桌面，不开额外隔离页；启动索引清空并保留原始内容及属性 |
| 规则恢复 | 完整恢复启动索引、文件属性、悬浮窗权限、组件状态、网络链和 Windows 启动项，随后重新应用成功；临时实例网络规则也完成移除与重新应用 |
| 免 Root | MuMu 自带 Root 开关关闭时，官方管理通道、组件与网络规则可用；回退框架后原始系统盘只读开关恢复 |
| 可选 Root | KitsuneMagisk 31024 安装、Zygisk 开启、Vector 2.0 模块及两个管理器安装成功；MuMu 自带 Root 关闭后 `magiskd` 与 Vector 的 `lspd` 服务启动 |
| Root 回退 | 按上游事务恢复系统文件，移除两个管理器，恢复原始 Root 与系统盘设置；没有继续运行框架守护进程，测试 App 和数据仍在 |
| 上游下载 | 程序自身下载接口完成两个固定版本的下载与 SHA-256 核对；正式 EXE 不携带这两个第三方包 |
| APK | 通过 MuMu 官方安装入口安装签名样例成功；免 Root、广告过滤和商店悬浮窗限制开启时再次覆盖安装成功 |
| XAPK | MuMu 自带安装界面显示安装完成；APK 版本正确，`Android/obb` 下扩展文件实际落盘，内容一致 |
| App 更新 | 同签名测试 App 从 v1 覆盖到 v3，原有数据标记保留；Root 回退后标记及 OBB 仍在 |
| 资源下载 | App 内 HTTPS 请求返回 200，577 字节资源写入成功；框架启用和回退后均检查到成功结果 |
| MAA | 主实例、框架启用实例和回退后的免 Root 实例均连接成功，每轮连续五次有效 PNG，触控接口返回任务编号 |
| MAA 增强截图 | 主实例、免 Root 临时实例分别加载 MuMu 原生增强接口并选为截图方式；连续五次有效 PNG，保留 maatouch |
| MuMu 版本提示 | 独立更新器停用、原始文件恢复、再次停用均完成；关于页面不再显示“发现新版本／重启更新” |
| 后台助手 | 主窗口关闭后，事件监听助手空闲 CPU 累计时间在观察间隔内不增长；没有 Android 用户态常驻过滤代理 |
| 重启自动生效 | 当前主实例重启后，未再次点击去广告，IPv4/IPv6 与 UID 选择器自动恢复；原桌面未见推荐卡片或弹窗，MAA 增强截图再次通过 |
| 命令边界 | 同时读取 64 KiB 标准输出和 64 KiB 错误输出通过；长时间命令在约 15 秒终止，输出通道也设置了等待上限 |
| 构建与界面 | Windows .NET Framework 编译通过；主界面和 Root/更新窗口完成布局检查 |

Android 15 的原有 UID 匹配、CEF 路径、恢复目录兼容分支保留。本轮没有将当前 Android 12 安装重新升级到 Android 15；Android 15 的实机结果见 [1.4.0 检查记录](VALIDATION_1.4.0.md)，不把历史结果写成本轮重新实测。

Root 配置是独立可选功能，第三方框架存在额外开销与 App Root 检测差异；不包含在“去广告不改变游戏渲染与硬件设置”的范围内。Vector 2.2 在本轮 ROM 上出现广播接口错误，发布方案固定使用 2.0。没有测试所有 Xposed 模块。

没有完整跑遍 MAA 作战、基建及全部游戏，没有开展长期广告覆盖和启动速度对照，也不承诺未来厂商更新后永久有效。普通 App 的更新样例不能代替每款游戏的热更新验证。

公开文件不含本机恢复点、安装路径、实例标记、设备 ID、日志、截图、MuMu APK、测试签名私钥或测试虚拟机数据。
