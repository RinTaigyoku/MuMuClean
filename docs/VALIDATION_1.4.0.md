# 1.4.0 发布检查

检查日期：2026-11-04 至 2026-11-05。MuMuPlayer 国际版 6.8.9.0 / Android 15，MAA 6.21.3。下面只写实际完成的项目。

| 项目 | 结果 |
| --- | --- |
| 原桌面 | 默认 HOME 保持 MuMu 原桌面，横屏正常；观察到的桌面没有横幅、推荐卡片或弹窗 |
| 广告来源 | 商店启动任务请求平台弹窗接口，另有桌面推荐组件；新版关闭对应组件并限制已确认的推广配置域名 |
| 精确域名过滤 | 测试应用定向匹配时，推广域名连接被拒；同 IP 的其他域名、商店 API 和普通 HTTPS 仍可连接；撤销后推广域名恢复连接 |
| 用户 App 范围 | 正式规则仅选择原桌面和商店 UID，测试 App 不在名单内，原本被测的推广域名也可由测试 App 正常访问 |
| root 开启 | 组件、网络规则应用和恢复通过，ADB 保持普通 shell |
| root 关闭 | 官方管理通道可用，组件和 IPv4/IPv6 规则应用、恢复、重新应用通过，root 开关始终为关闭 |
| 自动生效 | root 开启和关闭实例的重启均检查到规则自动恢复，广告请求命中拒绝规则；没有打开额外 Android 页面 |
| APK | 签名样例通过 MuMu 原生安装入口实际安装成功 |
| XAPK | 通过 MuMu 原生 XAPK 安装界面完成安装，包和测试 OBB 文件均落盘，OBB 内容一致 |
| App 覆盖更新 | 同签名测试 App 从 v1 更新至 v3，版本正确，原始数据标记保留 |
| 资源更新样例 | App 内 HTTPS 下载并写入资源成功，577 字节，更新前后校验一致 |
| MAA | root 开启和关闭实例均连接成功，连续五次增强截图有效，触控接口正常返回；游戏弹窗触控曾实际验证响应 |
| 完整恢复 | Windows 自启动及本工具防火墙规则移除、启动索引和属性还原、悬浮窗权限和四组件原始状态恢复、Android 自有规则链移除；随后可重新应用 |
| 打包 | Windows 自带编译器构建，主 EXE 内嵌启动助手，不带 Android APK、私钥或 MuMu 文件 |

没有把 Android 框架中普通热更新代码认定为广告代码，也没有删除核心更新逻辑。已确认的广告推荐和追踪组件通过停用隔离，不修改厂商二进制。

这些检查不等于穷举所有 App、所有 MAA 任务或所有 MuMu 后续版本。完整作战任务未逐项完成；资源下载样例也不能代替每款游戏的热更新测试。游戏渲染、用户 App 网络、更新器和硬件分配不在本工具修改范围内。30 FPS 是单独的可选功能，使用时会降低流畅度。

发布包不包含测试用应用、用户截图、配置、设备标识、日志或本机安装路径。
